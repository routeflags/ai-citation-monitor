# レポートの算術を Lean で検証する（D21）

| 項目 | 内容 |
|---|---|
| 日付 | 2026-11-28 |
| 入力 | オーナー依頼「コードにある数式の Lean のカバレッジを充足」 |
| 前提 | D8（率の分母と定義）、D11（費用機能を持たない）、D19（スキーマが公開契約）、`CONTRIBUTING.md` の 7 つの不変条件、`documents/plan/20261128-lean-verification.md`（導入検討） |
| 決定 | **証明するのは算術だけ。** `proofs/` の Lean 4 で丸めと点差を証明し、Go 実装との橋は `proofs/rate-vectors.csv` にする。Lean はビルド・テスト・リリースに入れない |

## 決定

1. **対象はレポートに出る算術に限る**。`NewRate` の丸め（`1/16` は `6.2%`、`6.3%` ではない）、
   率が `100.0%` を超えないこと、`Delta` の合成則、シェア列の丸めの合計上限。
   証明は `proofs/Rate.lean` の `tenths_spec`・`tenths_le_1000`・`tenths_error`・
   `delta_add`・`delta_neg`・`share_column_bound` の 6 つ。
2. **モデルと実装は共有の入力ファイルで結ぶ**。`proofs/rate-vectors.csv`（770 行）を
   `internal/analysis/vectors_test.go` と Lean の両方が読み、両方が全行を再現できなければ
   ならない。片方だけを直すと両方が落ちる。
3. **Lean はツールに組み込まない**。`aicm` は単一バイナリ・CGO 無しのまま。
   `proofs/` は Go のモジュールに入らず、生成器は `//go:build ignore`。
4. **`make proof` で実行し、CI では別ジョブ**。`make check` には入れない（オフライン・高速の
   約束を守る。Lean のツールチェーンは `proofs/lean-toolchain` で固定）。
5. **証明しないものを決めておく**: 分母の選択（D8）、グループ横断の禁止、追記専用、
   操作順に依存する性質。これらは「どの集合を数えるか」の話で、Lean の定理にはならず、
   Go のテストと（必要なら）TLA+ の領分。

## 理由

- 率の算術は、このリポジトリで Lean のモデルが**ほぼ忠実**になる唯一の領域。URL 正規化は
  NFKC / IDNA / `net/url` に依存し、Lean では公理化するしかない（＝バグの場所を仮定する）。
- レポートは `20.0% (n=1/5)` と式そのものを出す。読者が手で検算できる以上、丸めの規則は
  決定的に書かれている必要がある。「シェアは合計 100%」と書けないことの根拠にもなる。
- 丸めと点差は、テストでは代表例しか押さえられない。全 `n`, `d` についての主張は定理にする価値がある。
- 一方で、実装との一致は結局テストでしか担保できない。だからこそ共有ベクタを契約にする。

## 影響

- `make check`（CI のゲート）は変わらない。`make proof` と CI の `proof` ジョブが増える。
- `docs/metrics.md` に丸めの規則（偶数丸め、`1/2000` の例外、シェア列の上限）を追記した。
- `CONTRIBUTING.md` に `make proof` の前提（elan）と「ツールには不要」を追記した。
- 率の表示規則を変えるときは、コード・`docs/metrics.md`・`proofs/Rate.lean`・`rate-vectors.csv` の
  4 つを同じコミットで揃える。生成器は `go run proofs/gen_vectors/main.go`。

## 未検証 / 既知の限界

> 2026-11-28 追記: 下の `1/2000` の穴は **D22 で解消** した。実装を厳密丸め（整数）にし、
> 共有ベクタに tie 族（`d ≤ 1000` と `d = 2000` の全部）を加えた。決定は
> `documents/decisions/20261128-rate-rounding.md`。

- **証明はモデルについてのもの**。Go の `NewRate` が同じ規則であることは、770 行のベクタが
  覆う範囲でしか保証されない（`internal/analysis/vectors_test.go`）。
- `float64` がちょうどの .5 を保持できない `1/2000` は、厳密な偶数丸めと 1 桁ずれる
  （`0.1%` 対 `0.0%`）。これは定理にせず、`docs/metrics.md` と `proofs/Rate.lean` の冒頭に
  書いてある。
- シェア列の定理は「丸め誤差の上限」であって、各行の丸め方が正しいことの証明ではない。
- CI は Lean を毎回ダウンロードする（キャッシュなし、200MB 程度、数分）。
- 実行した確認: `lean Rate.lean`（型検査）、`lean --run Rate.lean`（770 行全て一致）、
  `go test ./...`、`go test -race ./...`、`gofmt -l .`、`go vet ./...`。Lean の証明が
  空虚でないことは、ベクタを 1 行書き換えると `lean --run` が落ちることで確かめた。
