# AI Citation Monitor — Go開発指示書

- Repository: `ai-citation-monitor`
- CLI command: `aicm`
- Phase: 1 / MVP
- Language: Go（開発開始時点の安定版を採用し `go.mod` に固定）
- License: Apache-2.0（公開前に確定）
- Interface: CLI only。Web UI、Web APIサーバー、SaaSは実装しない。

## 1. 目的と計測上の限界

生成AIの検索付き回答について、引用URL、ブランド言及、質問別獲得率、競合ドメイン比較、期間別トレンドを再現可能な形で記録・集計するOSSを開発する。

- Phase 1のプロバイダーはOpenAIとGemini。**公式APIの検索・grounding機能**を使う。
- APIで観測した結果は、ChatGPT/Geminiの一般向け画面や全ユーザーの結果を代表しない。UI・レポート・READMEに明示する。
- 回答本文にURLが現れただけでは「引用」としない。プロバイダーが返す引用・groundingメタデータに基づき判定する。
- メタデータが欠けた場合は `unknown`。引用ゼロと混同しない。
- サイト所有権を確認しない第三者ドメインも競合として登録可能。ただし収集するのは公開AI回答に現れた引用のみ。

## 2. 技術選定

| 領域 | 採用 | 方針 |
|---|---|---|
| CLI | Cobra | `aicm` サブコマンド、ヘルプ、補完 |
| HTTP | 標準 `net/http` | `http.Client` と `Transport` を再利用、タイムアウトと context を必須化 |
| 並行処理 | goroutine + `errgroup` / semaphore | グローバルおよびプロバイダー別の並列上限 |
| レート制限 | `golang.org/x/time/rate` | API別のRPM制御、429/Retry-After対応 |
| 表示 | Lip Gloss + 表表示ライブラリ（最小依存） | TTY時のみ色・進捗。非TTYはプレーンテキスト |
| 設定 | TOML | 機密情報は環境変数で注入 |
| 永続化 | SQLite + `database/sql` | CGO不要のドライバーを優先しクロスコンパイルを容易にする |
| テスト | 標準 `testing`、`httptest` | 通常のCIで実APIは呼ばない |
| 配布 | GoReleaser / GitHub Releases | macOS arm64/amd64、Linux amd64/arm64、Windows amd64 |

SDK利用は必須ではない。OpenAI・Geminiの**最新の公式API仕様を実装時に確認**し、HTTPアダプターで対応する。モデル名、エンドポイント、検索ツール指定、メタデータのフィールド名を憶測で固定しない。仕様差異はアダプター内に隔離する。

## 3. Phase 1 スコープ

**必須**
1. `aicm init`：プロジェクト、対象ドメイン、ブランド別名、プロバイダー、予算を設定。
2. `aicm questions add|list|import`：質問ID、版、カテゴリー、言語を管理。
3. `aicm run [--provider] [--repeat] [--concurrency] [--dry-run]`：検索付き回答を収集。
4. `aicm report [--period] [--provider]`：引用率、言及率、質問カバー率、失敗・判定不能件数を表示。
5. `aicm competitors add|list|remove` と `aicm compare --period 30d`：競合ドメイン別の獲得率・引用シェア。
6. `aicm trends --interval daily|weekly|monthly --period 90d`：時系列と前期間との差分。
7. `aicm export --format csv|json|jsonl`：機械可読な結果出力。
8. SQLiteで回答原文、引用原文・正規化URL、計測条件、使用量、費用推定、失敗理由を保持。
9. APIキーの非保存、リトライ、タイムアウト、予算上限、Ctrl+C中断・再開。
10. README、ライセンス、CI、テスト、バイナリ配布。

**Phase 1の対象外**：Perplexity、MCP、Web UI、Webサーバー、GSC/Bing連携、GitHub Actions定期計測テンプレート、自動回答正確性判定、SaaS。

## 4. CLI UX

```bash
# インストール後
aicm init
aicm questions import questions.csv
aicm competitors add competitor.example
aicm run --provider openai --repeat 3 --concurrency 3 --dry-run
aicm run --provider openai --repeat 3 --concurrency 3
aicm report --period 30d
aicm compare --period 30d
aicm trends --interval weekly --period 90d
aicm export --format jsonl
```

- `init` は対話式と `--non-interactive` の両方に対応。
- `run` は開始前に質問数、予定呼出数、概算費用、予算残額を表示。`--yes` で自動化可能。
- `--json` は機械可読出力、`--quiet` は進捗非表示、`--verbose` は詳細ログ。JSON時は標準出力をJSON専用にし、ログを標準エラーに送る。
- エラーには修正可能な説明を付ける。APIキー、Bearerトークン、回答中の秘匿情報をログに出さない。
- 終了コード：0 成功、1 一般、2 設定、3 認証、4 API/通信、5 予算停止。部分成功はサマリーに件数を示し、CI利用者向けの厳格モードを提供。

## 5. データモデル

テーブル：`projects`、`questions`、`question_versions`、`competitors`、`runs`、`responses`、`citations`、`mentions`、`usage_records`、`schema_migrations`。

各 `responses` は少なくとも以下を保持：
- `run_id`、`question_id`、`question_version`、`repeat_index`
- `provider`、`model`、`api_endpoint_version`、`search_enabled`、`measurement_method=official_api`
- `started_at_utc`、`completed_at_utc`、`status=success|error|cancelled`
- `answer_text`、`raw_response_json`（認証情報は除去）
- `citation_observability=observed|unknown`、`error_code`、`error_message`
- `input_tokens`、`output_tokens`、`tool_usage`、`estimated_cost`、`cost_currency`、`cost_status=estimated|unknown`

`citations` は `raw_url`、`normalized_url`、`hostname`、`source_type`、`response_id` を保持。原文と正規化後を両方残す。UTC保存、表示時にタイムゾーン変換。DBマイグレーションを実装。

## 6. 指標の厳密な定義

すべての割合で、計測期間・プロバイダー・モデル・質問セット版・成功/失敗/unknownの母数を併記する。

- **GEO Citation Rate**：引用判定が可能な成功回答のうち、自社ドメインが1回以上引用された回答の割合。
- **Brand Mention Rate**：言及判定可能な成功回答のうち、ブランド名・登録別名に言及した回答の割合。曖昧一致は `unknown` として別集計。
- **AEO Question Citation Rate**：質問ごとの引用獲得回答数 ÷ 当該質問の引用判定可能な成功回答数。
- **AEO Question Coverage**：引用判定可能な回答が1件以上ある質問のうち、自社が1回以上引用された質問の割合。未計測とunknownのみの質問は別件数表示。
- **Competitor Citation Rate**：同一回答母集団における各ドメインの引用獲得回答率。同一回答で複数ドメインが引用されるため、合計は100%を超え得る。
- **Citation Share**：観測した各回答×ドメインのユニーク引用イベントを分母とするシェア。デフォルトは観測された全ドメイン、オプションで登録競合＋自社に限定。分母のスコープを表示。
- **Trend**：日・週・月ごとの各指標、件数、前期間との差（割合は percentage points）。初回は「履歴不足」。

同じ質問セット・質問版・プロバイダー・モデル・検索設定・繰り返し回数の比較を優先。異なる条件が混在する場合は警告し、共通条件のみで比較できる `--comparable-only` を提供する。期間ごとに質問数が変わるとカバー率が変動する点を明示。

## 7. ドメイン判定・URL正規化

- `net/url` で解析し、ホスト名を小文字化、末尾ドットと既定ポートを正規化。IDNを考慮。
- `example.com` と `sub.example.com` の一致はラベル境界を検証。`notexample.com` は不一致。
- `www` とサブドメインを含めるルールは設定で指定。公開サフィックスを考慮し、異なる組織のドメインを誤統合しない。
- URLのクエリやフラグメントを無条件に削除しない。正規化ルールを文書化する。
- リダイレクト追跡は任意・無効がデフォルト。追跡時はSSRF対策（プライベートIP、localhost、リンクローカル、リダイレクト先再検証、タイムアウト）を必須とする。

## 8. HTTP実行・安全性

- `http.Client` と接続プールを再利用し、`context.Context` を全リクエストへ伝播。
- プロバイダー別の同時実行数、RPM、必要ならトークン制限を設定。
- 429、502、503、504等の再試行可能なエラーのみ、`Retry-After` 優先＋指数バックオフ＋ジッターでリトライ。認証失敗等は再試行しない。
- リトライ回数と累計費用を記録。タイムアウトや不確定なレスポンスの再試行で重複課金の可能性を表示。
- `--dry-run` はネットワークAPIを呼ばない。概算不能なら `unknown` と表示し、ゼロ円扱いしない。
- 予算制御は実行前推定と実行中の保守的な上限チェック。API請求額の厳密な上限を保証できないことを明示。
- Ctrl+Cで新規ジョブ投入を停止し、完了済み結果をコミット。再開時は完了した `run_id + question_version + provider + model + repeat_index` を二重実行しない。

## 10. テスト・受け入れ条件

### 単体テスト
- URLのラベル境界、サブドメイン、IDN、重複引用、URL正規化。
- 引用メタデータ有無、本文中だけのURL、ブランド同名衝突。
- 成功/失敗/unknownの分母処理、質問カバー率、引用シェア。
- 競合比較、日週月集計、条件不一致時の警告、ゼロ件、履歴不足。
- 予算超過、429再試行、キャンセル、途中再開、重複防止。

### 統合テスト
- `httptest.Server` と固定FixtureでOpenAI/Geminiレスポンスを検証。
- SQLiteマイグレーション、永続化、再読込、CSV/JSON/JSONL出力。
- CLIの非対話モード、JSON出力、終了コード。
- 通常CIはAPIキー不要・外部API呼出なし。実APIのスモークテストは明示的に有効化し、課金と機密情報に注意。

### Phase 1 完了条件
1. Goの単一バイナリをmacOS/Linux/Windows向けに生成できる。
2. `aicm init → questions import → run → report` が動作する。
3. OpenAIとGeminiの公式検索付きAPIで引用メタデータを取得・保存できる（対応モデル・API条件を文書化）。
4. 競合ドメイン比較と日・週・月トレンドがCLIで表示できる。
5. 計測条件と母数がレポートに表示される。
6. API予算管理、レート制限、リトライ、中断・再開が動作する。
7. CSV/JSON/JSONL出力、README、テスト、CIが揃う。
8. 実API未検証の機能は「未検証」と報告する。

## 11. 実装順序とエージェント指示

1. 既存リポジトリを調査。既存実装を壊さず差分計画を作る。
2. Cobra・TOML・SQLite・設定・CLIの骨格を実装。
3. HTTP共通クライアント、制限・再試行・予算制御を実装。
4. OpenAIアダプターを実装しFixtureと実APIで検証。
5. Geminiアダプターを同じ契約で実装。
6. 引用・言及・AEO集計と母数のテストを完成。
7. 競合比較と期間別トレンドを実装。
8. エクスポート、CLI表示、README、CI、GoReleaserを整備。
9. `go test ./...`、`go vet ./...`、race検出（対応環境）を実行。
10. 完了項目・未検証項目・制限事項を明示して報告。

**禁止事項**：Web UIの追加、外部DBの必須化、根拠のない引用判定、架空のAPIフィールドの実装、APIキーの保存・ログ出力、Phase 2機能の先行実装。
